02 / Case studies

Three problems, and how I solved them.

Case 01N-LITE Sports · SPATSCORESecurity

Rejecting infected uploads before they reach storage

Problem
User uploads went straight to cloud storage. One bad file could sit there and get served to other users.
What I did
Added ClamAV scanning to the upload API. The file stream is scanned first, and only clean files are written to storage. At SPATSCORE, I ran it as a self-hosted scanning service over NATS.
Result
Infected files are rejected at the door and never stored.
Case 02RE²Data integrity

Two saves at once, one lost update

Problem
Session progress was saved as read, change, write. Tests passed, but they only sent one request at a time. Two saves arriving together would overwrite each other and silently lose data.
What I did
Wrapped the write in a transaction with row-level locking, so the second request waits for the first to finish.
Result
Concurrent saves no longer drop data.
Case 03Location-scoring platformQA & debugging

One fixed coordinate behind every score

Problem
Before launch, the location scores needed to be checked against real places, not just against what the code returned.
What I did
Led end-to-end QA: validated 16 Manhattan locations against their stored scores, logged every mismatch, and traced the biggest one to its source.
Result
Found that every headline score was being computed from fixed Times Square coordinates instead of each location's own.
